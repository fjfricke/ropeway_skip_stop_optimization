# Findings

This directory records empirical or structural observations that are not
obvious from the code and are not yet explained in the thesis.

A finding should include:

- date and relevant software commit;
- scenario, configuration, and measurement method;
- observed values;
- interpretation and limitations.

Findings do not contain future work lists. Follow-up ideas belong in
`docs/plans`. When the thesis fully incorporates a finding, keep this document
only if it remains useful as detailed experimental provenance.
